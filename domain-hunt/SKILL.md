name: domain-hunt
description: Domain hunt — find, check, grade, debate and register a product domain. Use when the user wants to name a product, find an available domain, check domain combos or prices, weigh domain candidates, or buy a domain.
---

A domain hunt runs as widening rounds: generate a batch, check it, curate what's open, and let the user steer. The user usually discovers what they want by reacting to real, available options. Make each report count by running several rounds silently first, so the table they react to is already wide.

## Checking availability

- **Cloudflare TLDs:** run `check.mjs <domains…>` from this skill's directory (Node 18+). It dedupes, sends batches of 20 to Cloudflare Registrar, and prints `OPEN name $price/yr` or `taken name reason`. Prices are Cloudflare's at-cost price. If it prints nothing or reports an auth error, ask the user to run `! npx -y cf@latest auth login` (a Cloudflare account is free).
- **Other TLDs:** when `check.mjs` says `extension_not_supported` (.si is one), run `whois-check.sh <names…>` instead. All names in one call must share a TLD. It finds the registry's WHOIS server through IANA and compares each answer against a nonsense name's answer, so registry boilerplate can't cause false "taken" results. It doesn't report prices. Look up a real registrar's price (for example dynadot.com/domain/<tld>) and cite it rather than estimating.
- **Generating combos:** wrap the loops in `bash -c '…'`. The user's shell is zsh, which doesn't word-split `$var`, so a loop over a variable runs once on the whole string.

## Steps

1. **Pin the real use.** Before generating anything, find out where the domain will actually appear: an email address people print (`slug@domain`), a URL said aloud, a consent screen, or a handle. Also note naming rules the project already has (for example PRODUCT.md or a brand doc). Done when you can write one concrete example of the domain in use, such as `brecksvilledental@example.ai`.

2. **Run rounds, then report.** Each round is one idea direction, checked in bulk with 100–200 names generated by a shell loop:
   - **Real words and obvious compounds.** Expect these to be nearly all taken on .com, .ai and .co. One round shows that.
   - **Thesaurus combos.** Take the user's favorite word, expand it with real synonyms, and cross them with prefixes and suffixes that fit the product (`get`, `try`, `hq`, or a category word like `agent` or `studio`).
   - **Swap the anchor word.** Keep the suffix the user likes and replace the prefix, or the reverse.
   - **Metaphor vocabulary.** Use the trade terms of the world the product borrows from, such as retail shelf words for a product about being chosen.
   - **Exact name variants.** `the…`, `get…`, plurals, and other TLDs when the .com is taken.

   Run at least three directions before the first report. When the user asks for more, run at least two more before reporting again. Each report is one ranked table of open names, merged across every round so far:

   | # | Domain | Grade | Price | Direction | Why |
   |---|--------|-------|-------|-----------|-----|
   | 1 | grangerroadauto.com | A | $10.46/yr | Road name | Short, says what the shop does, survives the phone |
   | 2 | grangerautomotive.com | B+ | $10.46/yr | Short brand | Clean, but "Granger Auto" is taken elsewhere, so check for collisions |

   Grade each name quickly against the step-3 criteria and say in "Why" what moved it up or down. Rank by grade first. Among equal grades, rank shorter and cheaper names higher. Direction groups names by what they *mean*, so the user can steer by direction.

   Under the table:
   - Your top pick, in one line.
   - Dropped names in one line with reasons: forced or too-cute names, names that mean something else to the audience, collisions with known companies (for example Deputy or Envoy).
   - Exhausted directions in one line.

   Done when the user names a direction or a finalist.

3. **Grade finalists in real use.** Put each finalist into the step-1 example. Score it in a table with one column per criterion (✓, ~ or ✗), a letter grade, the price and a one-line reason:
   - **Self-identifying:** does the reader the address is for (for example an AI agent) know it's meant for them from the words alone?
   - **Counter test:** can someone say it aloud once, across a counter or on the phone, and be understood without spelling it out?
   - **Spelling:** is there only one obvious way to type it? Watch for words that run together (`agentsentrance`), plurals lost in speech, and for/four.
   - **Trust:** does the TLD fit the audience? .com is safest for small businesses, and .ai is normal for AI products. When a TLD is riding a news trend (.si after the US "Super Intelligence" rename), research its adoption with sources before grading it.

   Grade on this scale: **A** passes all four; **B** has one soft spot (~); **C** fails one (✗); **D** fails two or more. Add + or − to break ties. Sort by grade. Done when every finalist has a row.

4. **Debate before recommending a purchase.** Follow [DEBATE.md](DEBATE.md): argue your pick against Codex in herdr until you agree on a buy list. Any new evidence the user brings afterward goes back through the debate. Done when the user has the consensus buy list (domain, role, cost per year, registrar).

5. **Compare prices** if the user asks: `vercel domains price <domain…>` (if they have the Vercel CLI) against the Cloudflare price. Note term minimums: .ai requires two years, so the first charge is double the yearly price.

6. **Register only on an explicit go.** Registration is billed and can't be refunded.
   1. Run `npx -y cf@latest registrar registrations check <domain…>` to confirm the registration and renewal prices.
   2. Show the review screen:
      ```
      npx -y cf@latest registrar registrations create <domain> --body '{"domain_name":"<domain>","years":1}' < /dev/null
      ```
      With stdin closed it stops at the confirmation, so nothing is charged. It shows the term, the amount due, auto-renew (off by default) and WHOIS privacy. Tell the user these. The skill used to say `--dry-run` here, but that fails at schema loading and should not be used.
   3. Run the same command with `--force`.
   4. If it fails with "No registrant contact provided", Cloudflare has no default contact. Send the user to `https://dash.cloudflare.com/<account-id>/domains/registrations` (the account ID is on the review screen) to add one, or to buy in the dashboard. Leave contact details to the user.
   5. Confirm with `npx -y cf@latest registrar registrations get <domain>`.

   Done when the status is `active`. Report the expiry date and the auto-renew setting, and offer to set up any redirects the buy list calls for.

## Traps

- Searching before step 1 produces names graded on sound alone. The real use is what separates finalists.
- Open domains always go in a ranked table with grade, price and reason. Bulleted lists don't count.
- Summarize taken names as exhausted directions in one line.
- Availability isn't trademark clearance. Say so when recommending, and offer a separate check.
